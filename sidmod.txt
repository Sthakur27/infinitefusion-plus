smart trainer ai v3 - beam search + expected-damage term (and a display bug fixed)
055_sidmod/SmartTrainerAI.rb
  BEAM SEARCH over an ABSTRACT state (sidmod_action_table / sidmod_beam_step /
    sidmod_beam_eval / sidmod_beam_values, ~line 330). Real tree search was PRICED FIRST and
    rejected: a search node must snapshot state, a party deep-copy is ~2 ms, so a joint 1-ply
    expansion is 81 nodes = 212 ms per decision (45x) and 2-ply = 17 SECONDS. So the beam does not
    touch the engine state at all - it builds a per-decision table of what each move does
    (damage / heal / chip+burn / boost), then searches a compact state
    [my_hp, their_hp, my_off_mult, their_off_mult, my_resid, their_resid, my_statused, their_statused]
    with pure arithmetic. A node is microseconds. Opponent is modelled greedily (best attack).
    BEAM_DEPTH 3 full turns, BEAM_WIDTH 4, blended into the existing score as
    BEAM_WEIGHT * (value - mid_of_range) so it RE-RANKS rather than inflates.
    Measured: +0.044 winrate vs the same AI with the beam off (298-250 of 548 decided, 2.1 SE).
    Depth 3 beat depth 2 over 919 games (0.534 +/- 0.017, z=2.1); depth 4 added nothing; width and
    weight variants were all flat, so those stay at 4 / 130.
  DMG_WEIGHT (~line 460): expected damage as a fraction of the target's remaining HP, added when no
    KO is available. The vanilla effect-score library rewards secondary effects, so it ranked a
    RESISTED Waterfall (230) above a neutral STAB Earthquake (214) on a Huge Power attacker, and the
    beam's correct preference was too narrow a spread to overturn it. Side effect worth knowing: this
    also fixed heal-vs-weak-attack decisions, because a resisted poke now scores as the weak play it
    is - stall's recovery use per battle went 3.3 -> 7.3 and the stall archetype went from 0-6 to
    3-3 against the pool's six highest-KO mons.
  sidmod_ability_immune? (~line 250) REPLACES a call to the engine's pbImmunityByAbility.
    IMPORTANT BUG THIS FIXES: pbImmunityByAbility DISPLAYS the ability splash and the "It doesn't
    affect..." message, so calling it from the AI's scoring pass printed phantom battle messages -
    396 spurious lines across six sim battles, and in game the player would have seen ability
    popups while the AI was merely thinking. The replacement is a side-effect-free table
    (ABILITY_IMMUNE_TYPE / ABSORB_ABILITIES / GROUNDED_ANYWAY covers Water/Volt Absorb, Dry Skin,
    Storm Drain, Lightning Rod, Motor Drive, Flash Fire, Well-Baked Body, Sap Sipper, Levitate,
    Earth Eater, Wonder Guard, and Thousand Arrows/Smack Down ignoring Levitate).
  least-bad no-op ranking (~line 165): when every option is a no-op, a move the foe ABSORBS for HP
    is now ranked last, so the planner does nothing rather than healing the opponent.
  SmartAI.tune(side, key, default): numeric per-side override (sim only) so tuning variants can be
    played against each other instead of guessed at.
  cost: 3-5 ms per decision, ~0.08-0.16 s per battle - unchanged from v2 within machine noise.
  fairness re-verified after all changes: side 0 wins 46.6% of 240 games across varied teams and
    50.0% of 80 identical-team self-mirrors; draws 0.8%.

  OPPONENT SWITCH PREDICTION - BUILT TWICE, MEASURED, REVERTED. Since the beam already projects a
  state for free, predicting the pivot is just a second scenario. Attempt 1: evaluate "they pivot
  now" (our per-move damage recomputed against the incoming mon, so a move it is immune to reads as
  worthless) and blend by switch probability -> pivot-blanked hits got WORSE, 15 -> 23 per 112
  battles. Attempt 2: a narrow veto (only when a pivot is >=40% likely AND this exact move does
  literally nothing to the incoming mon) -> the targeted blunder dropped 15 -> 10, but TOTAL wasted

SMART AI - STRENGTH CEILING FOUND (read this before investing more in the AI)
  The plan-based SmartAI is EXACTLY AS STRONG AS THE STOCK ESSENTIALS AI it replaces.
  Measured with sim/naiversions.rb, identical teams + seeds, both side assignments:
    stock vanilla  vs  pre-session SmartAI : 0.572 +/- 0.023 (480 games)  -> vanilla WON
    stock vanilla  vs  current SmartAI     : 0.500 +/- 0.013 (1440 games) -> dead even
    pre-session    vs  current             : 0.428            (480 games)
    ELO with stock = 0: current +0, additive-only variant +0, pre-session -37
  So the "strategic layer" as it shipped before this session was ~37-41 ELO WORSE than the
  vanilla AI it overrode - its multipliers (STATUS_TIGHT_MULT 0.35, DOOMED_MULT 0.55 etc)
  suppressed the vanilla effect-score library's already-sane healing/status play. The v2/v3
  work recovered exactly that regression and no more. An additive-only variant (every
  suppressive multiplier disabled, feature :suppress) also lands at 0.495 - i.e. the
  suppression is not the whole story; 1v1 tactical scoring is simply at its ceiling here.

  THINGS TRIED THAT DID NOT BEAT STOCK (all measured, do not redo blindly):
    deeper search      beam depth 3 -> 4: nothing. Engine-state cloning is fatal (2 ms/node,
                       2-ply joint = 17 s/decision), so a real tree search is off the table.
    switch prediction  two implementations (blended scenario, narrow veto). The veto DID cut
                       the targeted blunder 15 -> 10 per 112 battles, but total wasted turns
                       were unchanged and winrate was 0.491-0.492 over ~1200 games. Reverted.
    team-level planning threat/answer analysis across both parties: preserve a scarce answer,
                       protect a boosted win condition, do not sack a sole answer. Marginal
                       0.501; vs vanilla still 0.500 over 1440 games - with BOTH a cheap
                       offence/bulk proxy AND a proper type-aware party-vs-party matchup
                       (sidmod_pkmn_vs_pkmn). Kept (it is cheap and principled) but it buys
                       no measurable strength. Feature gate :team.
    weight tuning      beam width/weight variants all flat; not pursued further because
                       tuning a framework worth +0 cannot be worth much.

  WHAT THE WORK DID BUY (and why it is still worth shipping):
    - a 37-41 Elo REGRESSION fixed: the AI Sid was actually playing against was worse than
      stock, and now it is not.
    - blunder elimination: wasted (no-op) moves 191 -> 0 per 6 battles, recovery-move usage
      0.8% -> correct, immunity clicks respected, no phantom ability messages, statuses a wall
      it cannot out-race, phazes a boosting sweeper, does not feed replacements into free KOs.
      An opponent that Hazes into nothing 36 times LOOKS broken even when it wins - for a
      single-player game this is worth more than the 0 Elo it measures.
    - a difficulty/style knob: SmartAI.feature? / SmartAI.tune take per-side overrides, so the
      same engine can express aggressive / stalling / balanced trainers.
    - a measurement harness that can actually settle these questions (see RUNBOOK 3c).

  METHOD LESSON (the important one): for MONTHS the only baseline used was "the previous
  SmartAI", so a regression against stock went unnoticed. Always measure a game-AI change
  against the STOCK AI, and remember that self-play ablation is blind to any fix both sides
  benefit from equally (six correct fixes each measured ~0.500 individually but were worth
  +10.4 collectively against the pre-session build).

  RECOMMENDATION: stop investing in AI STRENGTH - the measured headroom on this axis is zero.
  If more AI work is wanted, spend it on VARIETY (per-trainer personalities via the existing
  tunables) rather than on trying to out-score the vanilla library.
